# 技术说明

`sdd.py` 是上下文 CLI。`ingest` 将规格、代码、测试与内容摘要导入 seekdb 的 `sdd_minimax_material_v1` 表。`context` 用数据库全文查询针对每类资料取一条有匹配分的结果，输出文件路径、正文、摘要、得分和查询语句输入。课程归档 CSV 的规格是独立干扰项。重新导入同一 corpus 时，事务替换该 corpus 的记录，避免旧规格参与检索。

PowerContext 按 corpus 创建独立 Scope。基线验证进程保存功能断言失败、原行为通过和待办事项。后续 CLI 进程通过 `context/prepare` 读取保存的状态，并将恢复的状态加入模型输入。本次实测通过 MiniMax Code 网页版的 M3.1-Flash 生成订单报告模块的候选版本。应用保留原始样例，在同一个测试入口分别验证基线和候选，记录代码与测试的摘要、退出码和差异。

已用真实 seekdb 1.4.0.0 和 PowerContext 验证资料检索、规格更新后重新检索、基线行为、写入状态和跨进程恢复。MiniMax 生成的候选保留原有筛选行为，添加整数分门槛并按规格拒绝非法输入，4 项功能测试和 3 项回归测试均通过。验证后写入新检查点，独立 CLI 进程读回候选摘要与测试结果。此样例使用英文全文关键词和项目内的三类材料，面向小型可复现验收。
